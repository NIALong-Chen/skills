# resume skill

## 先确定当前任务与依据

- 使用当前简历、最新编辑和本轮要求作为依据。不要把旧写作块覆盖到已按批注更新的文件上。
- 已有文件和事实足够时直接工作；没有简历时请用户提供文件、截图或文字。没有JD可先做通用版，不阻塞。
- 从当前简历及用户确认中记录项目归属、数据口径与个人偏好；当前文件及新确认优先。不在公开技能中保存个人履历、联系方式、薪资或私有文件标识。
- 区分局部文字、某家公司完整经历、整份简历和文件导出。用户只要一段文字时，只返回该段；用户说“重新导出”时实际生成文件。沿用当前文件格式，未指定格式且无现有文件时默认PDF。
- 对批注逐条定位，合并此前已确认的修改。缺失截图但文字批注明确时继续；需要图片或照片时先检查原文件的现有资产。

## 内容诊断与改写

1. 先判断经历对目标岗位的相关性、个人负责范围、可验证成果及重复内容；不要只润色措辞。
2. 将口语记录整理为“行动＋工作对象/范围＋目的或实际结果”。删去重复提醒、流水账和过细的内部操作；保留能体现判断、协调、风险处理和交付能力的信息。
3. 优先突出与JD匹配的经历。没有JD时，按最近且相关的经验组织通用版，不凭空赋予产品战略、人员管理、预算或营收职责。
4. 严格保留贡献层级：协助、参与、负责、独立、主导不可随意升级。没有证据不写提高效率百分比、降低成本或显著增长。
5. 对缺失事实提出少量关键问题：具体个人动作、难点、产出、统计区间、量化口径。可先改写有依据的内容，不把假设写进定稿。
6. “职责”解释做什么及如何推进，“业绩”集中呈现结果与规模。避免职责和业绩逐句重复；没有独立业绩可把结果写进职责。
7. 根据公司、项目、时间段建立数据归属。同项目工作变化应合并；不同项目即使职责相近也保留归属。公司级业绩只有在统计互不重叠、单位可比时才能相加。
8. 区分需求交付与需求转测、问题单关闭与转测、版本与大版本、客户满意度与NPS、响应与解决时间。不得把“按时通过检查”改成“首次通过率100%”。
9. 保持语言简洁、具体、HR易读。保留必要行业词汇；未知缩写不要猜全称。

## 输出与迭代

- 内容稿用清晰分组及简短要点；完整可复制的文字按 writing-blocks 技能呈现。
- 不额外添加确认关卡。用户已要求导出或格式修改时，直接完成、检查并交付。
- 不把一个候选人的数据推广到其他候选人，也不把技能中历史薪资和工作年限自动视为当前事实。
- 若讨论期望薪资，核实城市、税前税后、月薪与薪数等重要口径；可先明确假设后给区间。查询当前招聘样本，区分挂牌薪酬与实际报价；将个人判断标为建议，比较固定年薪与工时福利，不保证录用或涨幅。

## 排版与文件处理

- 默认采用 [排版与质量检查](references/layout-and-qa.md)；用户本轮明确要求优先。
- 使用 documents 技能处理Word，使用 pdf 技能处理PDF的生成、读取和渲染检查。复用当前工作文件，不因小改动重建无关内容。
- 使用 Library 技能保存用户文件；更新现有文件时保留同一身份及版本历史，新副本仅在用户要求时创建。
- 渲染受影响页面并目视检查后交付。最终简短说明修改结果并提供文件链接；不展示内部存储或工具细节。
